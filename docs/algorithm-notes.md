# 복습·새 단어 선정 알고리즘 노트

## 결론
- **간격 계산식(현재 SM-2 변형)은 그대로 둬요.** FSRS-6를 구현하고 공식 구현과 대조까지 마쳤지만, 시뮬레이션에서 현재 방식보다 낫다는 근거를 얻지 못했어요(초반 하루 복습량은 오히려 많았어요). 실제 학습 기록이 쌓이기 전에는 바꿀 이유가 약해요.
- **새 단어를 넣는 규칙을 바꿨어요.** 예전 "밀림 120/180장" 제한은 거의 작동하지 않았어요. 지금은 **하루 복습 상한**(기본 250번)에서 오늘 예정된 복습을 빼고 남는 만큼만 새 단어를 넣어요. 시뮬레이션에서 하루 최대 복습은 크게 줄고, 160일 뒤 기억률은 같았어요.
- **기억을 더 단단하게 하는 방법은 "더 자주 복습"뿐이에요.** 그래서 **기억 강도**(표준 1.0 / 강화 0.85 / 최대 0.7) 설정을 넣었어요. 복습 단계 카드의 다음 간격에 배율을 곱해요. 기본값은 강화예요.

## FSRS-6 검토
- 구현: `docs/experiments/fsrs6.js`. 공식 기본값과 공식을 그대로 옮겼고 5단계 평가를 FSRS 4단계에 대응시켰어요(몰랐음·틀림→다시, 비슷함→어려움, 맞았음→보통, 알고 있음→쉬움).
- 검증: 독립적으로 다시 옮긴 `docs/experiments/fsrs_reference.py` 와 무작위 평가 순서 400개(5,406단계)를 비교했고 **불일치 0건**이에요(안정도 상대오차 0.03% 이하, 난이도 오차 0). R(t=S)=0.9, 목표 90%의 간격=S 같은 기준점도 맞았어요. 공식 파이썬 패키지를 직접 설치해 대조하지는 못했어요.
- 시뮬레이션(`node docs/experiments/simulate.mjs scheduler`, 5명 평균, 120일, 1,200단어, 하루 60개): 정답 기억 모델은 FSRS와 다른 매개변수의 거듭제곱 망각(가정)이에요.

| 학습자 | 방식 | 총 복습 | 하루 최대 | 120일 기억률 |
|---|---|---|---|---|
| 보통 | 현재 방식 | 9,693 | 295 | 96.3% |
| 보통 | FSRS-6 목표 90% | 11,716 | 514 | 96.6% |
| 느린 기억 | 현재 방식 | 13,898 | 355 | 95.3% |
| 느린 기억 | FSRS-6 목표 90% | 13,450 | 558 | 94.3% |
| 빠른 기억 | 현재 방식 | 8,105 | 260 | 97.2% |
| 빠른 기억 | FSRS-6 목표 90% | 11,015 | 499 | 97.8% |

- 관찰된 기억 비율로 간격을 보정하는 단순 장치(현재 방식·FSRS-6 모두에 붙여 봄)도 결과가 몇 % 안에 모였어요. 합리적인 간격 방식들은 비슷하게 동작한다는 일반적인 이해와 맞아요.
- **다시 검토할 조건:** 복습 기록(`review_log`)이 사용자당 수천 건 쌓이면 그 기록으로 FSRS 매개변수를 맞춰서 현재 방식과 예측 정확도를 비교해 볼 수 있어요. 지금은 그 데이터가 없어요.

## 새 단어를 넣는 규칙 (`node docs/experiments/simulate.mjs intake`)
현재 간격 방식, 1,200단어, 160일, 5명 평균. 새 단어 한 개는 첫날 복습 화면을 평균 2.5번쯤 만들고 이후 며칠도 복습을 늘려서, 여유 있게 3.5번으로 계산해요.

| 학습자 | 새 단어 정책 | 다 넣는 데 | 하루 최대 | 160일 기억률 | 총 복습 |
|---|---|---|---|---|---|
| 보통 | 제한 없음(60개/일) | 20일 | 295 | 96.3% | 10,253 |
| 보통 | 예전 앱 규칙(120/180장) | 21일 | 290 | 96.3% | 10,162 |
| 보통 | 상한 150번 | 48일 | 155 | 96.7% | 10,088 |
| 보통 | 상한 200번 | 33일 | 202 | 96.6% | 10,149 |
| 보통 | **상한 250번(기본)** | 25일 | 235 | 96.4% | 10,255 |
| 보통 | 상한 300번 | 21일 | 273 | 96.4% | 10,311 |
| 느린 기억 | 제한 없음 | 20일 | 355 | 95.3% | 14,942 |
| 느린 기억 | 상한 150번 | 57일 | 187 | 95.2% | 14,683 |
| 느린 기억 | 상한 200번 | 37일 | 241 | 95.4% | 15,078 |
| 느린 기억 | **상한 250번(기본)** | 27일 | 279 | 95.4% | 15,098 |

새 단어를 천천히 넣어도 기억률과 총 복습은 거의 같고, 대신 하루 부담이 줄고 다 넣는 날짜가 늘어요. 시험 날짜가 가까우면 상한을 높이거나 "제한 없음"으로 바꾸세요.

## 기억 강도 (간격 배율, `node docs/experiments/simulate.mjs scheduler` 기반)
현재 스케줄러에 배율만 곱한 시뮬레이션이에요. 1200단어, 120일, 5회 평균. **기억 모델 가정에 크게 좌우되는 수치라 실제 기록으로 확인한 값이 아니에요.**

| 학습자 | 배율 | 복습 횟수 | 120일 시점 기억 유지율 | 하루 최대 복습 | 복습 시점 기억률 |
|---|---|---|---|---|---|
| 보통 | 1.0 (표준) | 9,693 | 96.3% | 295 | 93.8% |
| 보통 | 0.85 (강화) | 10,558 | 98.2% | 319 | 94.5% |
| 보통 | 0.7 (최대) | 11,456 | 98.9% | 349 | 96.9% |
| 보통 | 0.55 | 13,229 | 99.2% | 381 | 98.5% |
| 느린 기억 | 1.0 | 13,898 | 95.3% | 355 | - |
| 느린 기억 | 0.85 | 14,828 | 97.0% | 394 | - |
| 느린 기억 | 0.7 | 15,469 | 98.2% | 416 | - |
| 느린 기억 | 0.55 | 17,360 | 99.0% | 449 | - |

- 강화(0.85)는 복습이 약 9% 늘고 잊은 단어 비율이 절반쯤으로 줄어요. 0.7보다 더 줄이면 복습만 늘고 이득은 작아져요(수확 체감).
- 시험 날짜까지 남은 기간 비율로 간격을 제한하는 방법은 시험 당일 기억률이 ~100%에 가깝지만 복습이 1.7~2.7배 필요해서, 전체 배율보다 효율이 낮았어요. 그래서 넣지 않았어요.
- 앱의 **기억 점검**(통계 탭)은 "복습에서 기억해 낸 비율"(= 복습 단계 카드에서 맞았음·알고 있음을 고른 비율)과 "1초 안에 답을 확인한 비율"을 보여 줘요. 자기 평가라 실제 기억률과 다를 수 있어요(부분적으로 맞은 걸 "맞았음"으로 매기는 경향).

## 기록해 둘 점: 처음 시뮬레이션의 오류
처음에는 새 단어의 반감기를 0.6일로, 망각을 지수 곡선으로 가정해서 "FSRS가 복습을 약 40% 줄인다"는 결과가 나왔어요. 사람의 망각은 거듭제곱 형태로 꼬리가 길고 FSRS 기본값도 그렇게 맞춰져 있는데, 제 가정이 현재 방식에만 불리하게 설정된 착시였어요. 가정을 바로잡고 다시 돌리자 그 차이는 사라졌어요. 시뮬레이션은 가정에 크게 좌우되므로 절대 수치가 아니라 같은 조건의 비교로만 읽어야 해요.

## 한계
- 정답 기억 모델은 가정이고, 학습자는 매일 예정된 복습을 모두 하는 이상적인 경우예요. 며칠 쉬는 경우는 넣지 않았어요.
- 시뮬레이션의 복습 횟수는 평가 한 번을 한 번으로 세요(학습 단계의 반복 포함).
- 이 앱의 실제 사용 기록으로 검증한 것이 아니에요.
